GUI Tools for Managing WDAC
on Windows Server 2025

Which graphical tools exist, which one to choose, and how to install and use it step by step.

Short answer

Yes — use the Microsoft App Control Wizard (formerly "WDAC Wizard").

It is free, made by Microsoft, and covers the whole policy job in a GUI: create, edit, merge, turn audit events into rules, and compile to .cip. Install it on a management server with Desktop Experience or a Windows 11 admin workstation, then push the policies it produces to your Server 2025 machines (including Server Core) with CiTool, Group Policy or Configuration Manager.

Important: there is no single GUI that both authors and deploys WDAC to Windows Server. You combine a build tool (App Control Wizard) with a deploy tool (GPMC, Configuration Manager or a CiTool script) and a monitor tool (Event Viewer or the Microsoft Defender portal).

Which one is better, and why

For building and maintaining policies for Windows Server 2025: App Control Wizard.

1. Official and freeBuilt and maintained by Microsoft, open source on GitHub, no licence needed.
2. CompleteEvery rule type and every rule option, base and supplemental policies, multiple-policy format.
3. Learns from your serversTurns audit events (3076/3077) from a server's log or an exported .evtx into rules.
4. Standard outputProduces normal XML and .cip files, so it fits CiTool, Git, GPO and every script in your other guides.
5. SafeRuns on your admin machine; nothing is pushed to servers until you deploy it.
6. Easy to learnPage-by-page wizard with explanations for each option.

Recommended setup

Why not install the Wizard on every server? Production servers should run only what they need. One hardened management machine is easier to protect, and Server Core cannot run the Wizard anyway.

If the management machine itself runs an enforced WDAC policy, make sure the policy allows the Wizard (it is a Microsoft-signed packaged app). AllowMicrosoft trusts it; a strict DefaultWindows policy may need a rule for it.

Install the App Control Wizard

Two methods: online (with a browser) and offline (copy the file).

Method A — online, on the management machine

  1. Find the official download. Open Microsoft Learn and search for "App Control Wizard". The page links to the official download site (at the time of writing https://webapp-wdac-wizard.azurewebsites.net). Always start from Microsoft Learn so you get the genuine package.
  2. Download the MSIX file to C:\Install\.
  3. Check the signature before installing: 
    Get-AuthenticodeSignature C:\Install\*.msix | Select-Object Status, @{n='Signer';e={$_.SignerCertificate.Subject}}
    Expect Valid and a Microsoft Corporation signer.
  4. Install it. Double-click the file (App Installer), or use PowerShell — this works even where App Installer is missing, which is common on Server: 
    Add-AppxPackage -Path (Get-ChildItem C:\Install\*.msix | Select-Object -First 1).FullName
  5. Confirm the install. 
    Get-AppxPackage | Where-Object { $_.Name -match 'WDAC|AppControl' } | Select-Object Name, Version, InstallLocation
  6. Start it from the Start menu (search "App Control"). Right-click → Run as administrator when you need to read local event logs.

Method B — offline / no browser on the server

  1. Download and verify the MSIX on an internet-connected admin PC (steps A1–A3).
  2. Copy it to the management server: 
    $s = New-PSSession -ComputerName MGMT01
Invoke-Command $s { New-Item -ItemType Directory C:\Install -Force | Out-Null }
Copy-Item C:\Install\*.msix -Destination C:\Install\ -ToSession $s
  3. On the management server (interactive session, Desktop Experience): 
    Add-AppxPackage -Path (Get-ChildItem C:\Install\*.msix | Select-Object -First 1).FullName

Method C — install for all users of the management server

# Provision the package so every admin who signs in gets it
Add-AppxProvisionedPackage -Online -PackagePath (Get-ChildItem C:\Install\*.msix | Select-Object -First 1).FullName -SkipLicense

First-run settings

  1. Open Settings (gear icon) in the Wizard.
  2. Set the default output folder to your policy repository, e.g. C:\WDAC\Policies.
  3. Turn on convert policy to binary (so a .cip is created with each XML) if the option is shown.
  4. Leave the default policy format as multiple policy format for Server 2025.

Six common tasks in the Wizard

Task 1 — Create a base policy for a server

  1. Policy Creator → Multiple Policy Format → Base Policy.
  2. Choose Default Windows Mode (or Allow Microsoft Mode for SQL/Exchange servers). Enter a name, e.g. Srv2025-Base, and the save location.
  3. On the Policy Rules page turn on: Audit Mode, User Mode Code Integrity, Update Policy without Rebooting, Allow Supplemental Policies. For pilots also Advanced Boot Options Menu and Boot Audit on Failure.
  4. Skip custom rules for now → Next. The Wizard writes Srv2025-Base.xml (and the .cip if enabled).

Task 2 — Add a rule for a third-party application

  1. Policy Editor → open Srv2025-Base.xml (or create a supplemental, Task 3).
  2. Add Custom Rule → Rule type Publisher → browse to the app's signed EXE.
  3. Use the slider to choose how specific: issuing CA → publisher → product → file name → version. "Publisher + file name + version" equals FilePublisher.
  4. For unsigned files choose rule type File Hash; for an admin-only folder choose Path.
  5. Create Rule → Next to save.

Task 3 — Create a supplemental policy

  1. Policy Creator → Supplemental Policy.
  2. Browse to the base policy XML it extends (the base must allow supplementals).
  3. Name it with the ticket number, e.g. Supp-VendorApp-REQ1234.
  4. Add publisher/hash/path rules for the app → Next.

Task 4 — Turn audit events into rules

  1. On a pilot server running the base in audit mode, export the log: 
    wevtutil epl Microsoft-Windows-CodeIntegrity/Operational C:\Temp\CI-$env:COMPUTERNAME.evtx
# copy it to the management machine
  2. Wizard → Policy Editor → Parse event log (.evtx) files → select the file(s).
  3. Review the list of files found. Untick anything you do not recognise.
  4. Choose the rule level for each (prefer Publisher) → save as a new supplemental policy.
Audit events include everything that ran — possibly malware. Review every entry before creating rules.

Task 5 — Change rule options (audit → enforce)

  1. Policy Editor → open the base XML.
  2. Policy Rules page → turn Audit Mode off. Turn off pilot-only options (9, 10) for production.
  3. Save. Then raise the version (the Wizard may do this automatically; check VersionEx in the XML): 
    ([xml](Get-Content C:\WDAC\Policies\Srv2025-Base.xml)).SiPolicy.VersionEx

Task 6 — Merge policies

  1. Policy Merger → add the policies, e.g. your base and the driver blocklist C:\Windows\schemas\CodeIntegrity\ExamplePolicies\RecommendedDriverBlock_Enforced.xml.
  2. Choose the output path → Merge.
  3. Open the result in Policy Editor and confirm the name, ID and options are what you expect.

Deploy what you built

The Wizard builds files; these methods put them on servers.

Option 1 — CiTool over PowerShell remoting (works for Server Core)

$xml = "C:\WDAC\Policies\Srv2025-Base.xml"
$id  = ([xml](Get-Content $xml)).SiPolicy.PolicyID
ConvertFrom-CIPolicy -XmlFilePath $xml -BinaryFilePath "C:\WDAC\Binary\$id.cip"     # skip if the Wizard already made it

foreach ($srv in Get-Content C:\WDAC\pilot.txt) {
  $s = New-PSSession -ComputerName $srv
  Copy-Item "C:\WDAC\Binary\$id.cip" -Destination "C:\Windows\Temp\$id.cip" -ToSession $s
  Invoke-Command $s { param($id) CiTool.exe --update-policy "C:\Windows\Temp\$id.cip"; CiTool.exe -lp | Select-String $id.Trim('{}') } -ArgumentList $id
  Remove-PSSession $s
}

Option 2 — Group Policy (one policy only)

See the GPMC section. Build the policy in the Wizard using Single Policy Format for this method.

Option 3 — Configuration Manager

See the MECM section.

Store each Wizard output in Git with a commit message that includes the version and ticket. Deploy to a pilot ring first.

Update and uninstall the Wizard

# Which version is installed?
Get-AppxPackage | Where-Object { $_.Name -match 'WDAC|AppControl' } | Select-Object Name, Version

# Update: download the newer MSIX from the official site, then
Add-AppxPackage -Path C:\Install\<new-version>.msix

# Uninstall
Get-AppxPackage | Where-Object { $_.Name -match 'WDAC|AppControl' } | Remove-AppxPackage

Check for a new version every quarter; Microsoft adds features and fixes regularly.

Group Policy Management Console (deploy)

Deploy one policy to domain-joined Server 2025 machines without scripts.

  1. Install GPMC on the management server: 
    Install-WindowsFeature GPMC
  2. Build a single-format binary and put it on a share that computer accounts can read: 
    ConvertFrom-CIPolicy -XmlFilePath C:\WDAC\Policies\Srv2025-Single.xml -BinaryFilePath \\fs01\WDAC$\SiPolicy.p7b
  3. Open gpmc.msc → create a GPO (e.g. WDAC - Pilot Servers) linked to the pilot servers OU.
  4. Edit → Computer Configuration → Policies → Administrative Templates → System → Device Guard → Deploy App Control for Business (older name: Deploy Windows Defender Application Control).
  5. Set Enabled and enter \\fs01\WDAC$\SiPolicy.p7b.
  6. On a pilot server: gpupdate /force and restart. Check with CiTool.exe -lp.
Limits: one policy only, no supplementals, and a reboot is needed. For base + supplemental designs use CiTool or Configuration Manager.

Event Viewer custom view (monitor)

One click to see all WDAC audits and blocks on a server.

  1. Save the XML below as C:\WDAC\WDAC-View.xml.
  2. Event Viewer → Custom Views → Import Custom View… → select the file.
  3. To view another server: Action → Connect to Another Computer…
<ViewerConfig>
  <QueryConfig>
    <QueryParams><UserQuery /></QueryParams>
    <QueryNode>
      <Name>WDAC - Audits and Blocks</Name>
      <QueryList>
        <Query Id="0" Path="Microsoft-Windows-CodeIntegrity/Operational">
          <Select Path="Microsoft-Windows-CodeIntegrity/Operational">*[System[(EventID=3076 or EventID=3077 or EventID=3089 or EventID=3099)]]</Select>
          <Select Path="Microsoft-Windows-AppLocker/MSI and Script">*[System[(EventID=8028 or EventID=8029)]]</Select>
        </Query>
      </QueryList>
    </QueryNode>
  </QueryConfig>
</ViewerConfig>
On Server Core, use this view from the management server by connecting remotely. The Remote Event Log Management firewall rules must be enabled on the target.

Microsoft Defender portal (fleet monitoring)

See App Control events from every onboarded server in one place.

If your Server 2025 machines are onboarded to Microsoft Defender for Endpoint, open security.microsoft.com → Hunting → Advanced hunting and run:

DeviceEvents
| where Timestamp > ago(7d)
| where ActionType startswith "AppControl"
| summarize Events = count(), Servers = dcount(DeviceName) by ActionType, FileName, FolderPath
| order by Events desc

Export the results to CSV — the App Control Wizard can turn an Advanced Hunting export into rules (Policy Editor → event log options).

Configuration Manager console

For estates already managed by MECM.

  1. Console → Assets and Compliance → Endpoint Protection → App Control for Business (older name: Windows Defender Application Control).
  2. Create Application Control Policy → choose Audit Only or Enforcement Enabled.
  3. Optionally add trusted folders/files. MECM automatically makes its own client a Managed Installer, so software it deploys is trusted.
  4. Deploy to a pilot collection, then wider collections.
MECM's built-in policies offer fewer options than the Wizard. Check the current Configuration Manager documentation for Windows Server support and supported versions before relying on it for Server 2025.

Community tools

AppControl Manager (open source, by an independent developer, available on GitHub and the Microsoft Store) is a modern, feature-rich GUI that can create, deploy, sign and monitor policies on the local machine.

ProsVery complete; local deploy and log views in one app; actively developed.
ConsNot a Microsoft product and not covered by Microsoft support. OS requirements may not include Windows Server — check the project page first.
Use it forLabs and learning. For production, prefer the Microsoft App Control Wizard unless your security team has approved it.

Best practices for GUI-based management

  • Install GUI tools on one hardened management machine, not on production servers.
  • Keep every policy the Wizard produces in Git; the GUI does not keep history for you.
  • Name policies with role + purpose + ticket (e.g. Supp-SQL-Backup-REQ221).
  • Check VersionEx after every edit; it must be higher than the deployed version.
  • Always test GUI-built policies in audit on a pilot server before enforcing.
  • Review event-generated rules line by line before saving.
  • Prefer Publisher rules in the Wizard's slider; use Hash only for unsigned files.
  • Use scripts (CiTool) for repeatable deployment; use the GUI for authoring and review.
  • Update the Wizard quarterly from the official Microsoft source only.
