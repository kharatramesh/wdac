2. Helper functions (paste once per PowerShell session)

# Return the PolicyID (GUID) of a policy XML
function Get-WdacId($Xml){ ([xml](Get-Content $Xml)).SiPolicy.PolicyID }

# Create a new lab policy from a template, with a new name and a new GUID
function New-LabPolicy($Name, $Template = "DefaultWindows_Audit.xml"){
  $x = "$W\Policies\$Name.xml"
  Copy-Item "$T\$Template" $x -Force
  Set-CIPolicyIdInfo -FilePath $x -PolicyName $Name -ResetPolicyID | Out-Null
  $x
}

# Back up the XML, then raise the version by one (10.0.0.0 -> 10.0.0.1)
function Step-WdacVersion($Xml){
  Copy-Item $Xml "$W\Backup\$((Get-Item $Xml).BaseName)-$(Get-Date -f yyyyMMdd-HHmmss).xml"
  $v = [version]([xml](Get-Content $Xml)).SiPolicy.VersionEx
  $n = [version]::new($v.Major, $v.Minor, $v.Build, $v.Revision + 1)
  Set-CIPolicyVersion -FilePath $Xml -Version $n.ToString()
  "Version $v -> $n"
}

# Compile the XML to {PolicyID}.cip and deploy it with CiTool
function Deploy-Wdac($Xml){
  $id  = Get-WdacId $Xml
  $cip = "$W\Binary\$id.cip"
  ConvertFrom-CIPolicy -XmlFilePath $Xml -BinaryFilePath $cip | Out-Null
  CiTool.exe --update-policy $cip
}

# List every file rule (Allow / Deny / FileAttrib) with its ID
function Show-WdacRules($Xml){
  $p = [xml](Get-Content $Xml)
  $p.SelectNodes("//*[local-name()='FileRules']/*") | ForEach-Object {
    [pscustomobject]@{ Type=$_.LocalName; ID=$_.ID; Name=$_.FriendlyName; FileName=$_.FileName; FilePath=$_.FilePath }
  }
}

# Remove file rules by ID, plus every reference and any empty wrapper left behind
function Remove-WdacRule($Xml, [string[]]$Id){
  Copy-Item $Xml "$W\Backup\$((Get-Item $Xml).BaseName)-$(Get-Date -f yyyyMMdd-HHmmss).xml"
  $p = [xml](Get-Content $Xml)
  foreach($i in $Id){
    @($p.SelectNodes("//*[@ID='$i' and (local-name()='Deny' or local-name()='Allow' or local-name()='FileAttrib')]")) |
      ForEach-Object { [void]$_.ParentNode.RemoveChild($_) }
    @($p.SelectNodes("//*[local-name()='FileRuleRef' and @RuleID='$i']")) |
      ForEach-Object { [void]$_.ParentNode.RemoveChild($_) }
  }
  foreach($t in 'FileRulesRef','DeniedSigners','AllowedSigners'){
    @($p.SelectNodes("//*[local-name()='$t' and not(*)]")) | ForEach-Object { [void]$_.ParentNode.RemoveChild($_) }
  }
  $p.Save((Get-Item $Xml).FullName)
}

# Read Code Integrity events as simple objects (field names come from the event XML)
function Get-WdacEvent([int[]]$Id = @(3076,3077), [int]$Hours = 24, [string]$Computer = $env:COMPUTERNAME){
  $f = @{ LogName='Microsoft-Windows-CodeIntegrity/Operational'; Id=$Id; StartTime=(Get-Date).AddHours(-$Hours) }
  Get-WinEvent -FilterHashtable $f -ComputerName $Computer -ErrorAction SilentlyContinue | ForEach-Object {
    $d = @{}; ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    [pscustomobject]@{ Time=$_.TimeCreated; Id=$_.Id; File=$d['File Name']; Process=$d['Process Name'];
                       Policy=$d['PolicyName']; SHA256=$d['SHA256 Hash']; ActivityId=$_.ActivityId }
  }
}
Why Step-WdacVersion? The built-in templates start at version 10.0.0.0. If you hard-code a smaller number such as 1.0.0.1, the "new" policy is actually older than the template. Raising the existing version by one avoids that mistake.

B1What WDAC is and why it matters

Goal: explain WDAC in one sentence and describe the problems it solves.

WDAC decides which code is allowed to run on a computer. It checks every program, library (DLL), driver, script and installer before it loads. If the policy does not trust the file, the file is blocked.

Allow-listAnything not trusted is blocked by default.
Kernel enforcedCode Integrity in the Windows kernel makes the decision.
Device-wideApplies to every user, including administrators.
CoversEXE, DLL, drivers (SYS), scripts, MSI, packaged apps.

Examples: six real situations and how WDAC handles them

Example 1Ransomware dropped in a public folderdefault deny

An attacker copies locker.exe to C:\Users\Public and runs it. No rule trusts it, so Code Integrity blocks it and writes event 3077.

Rule that helps: none needed. Not trusted = not allowed.
Example 2An administrator runs an unapproved toolapplies to admins

An admin downloads a portable utility. Being an administrator does not bypass WDAC. The tool is blocked until a rule is approved for it.

Rule that helps: the change process — request → supplemental policy (topic I8).
Example 3Attacker loads a known vulnerable driverkernel

"Bring your own vulnerable driver" attacks load a signed but flawed driver to gain kernel access. The Microsoft driver blocklist denies it.

Rule that helps: RecommendedDriverBlock_Enforced.xml (topic A4).
Example 4A built-in tool is abused ("living off the land")deny rule

Attackers use Microsoft-signed tools such as mshta.exe to run malicious content. A deny rule by original file name blocks the tool even if renamed.

Rule that helps: FileName deny (topic I3) and recommended block rules (topic A5).
Example 5A malicious PowerShell scriptscript control

Untrusted scripts are forced into Constrained Language Mode, which blocks the dangerous parts of PowerShell (.NET calls, Add-Type, COM).

Rule that helps: script enforcement (topic A1).
Example 6A trusted vendor releases an updatepublisher rule

The vendor signs every version with the same certificate. A publisher-based rule keeps trusting new versions without any policy change.

Rule that helps: FilePublisher or Publisher allow rules (topic I2).

B5Policy XML structure

Goal: read any policy XML and say what it does.

ElementMeaning
VersionExPolicy version, e.g. 10.0.0.3. Raise it on every change.
PolicyIDThe policy's own GUID. The .cip file must be named after it.
BasePolicyIDSame as PolicyID for a base policy; the base's GUID for a supplemental.
PolicyType (attribute)Base Policy or Supplemental Policy.

SigningScenarios131 = kernel, 12 = user mode. Contains the references that activate rules.

B6Audit mode vs enforce mode

Goal: deploy your first policy, watch it in audit, then enforce it.

Audit modeNothing is blocked. Windows logs event 3076 for each file that would be blocked.
Enforce modeUntrusted files are blocked. Windows logs event 3077.
SwitchOption 3 Enabled:Audit Mode present = audit. Remove it = enforce.
SupplementalsHave no mode of their own; they follow their base policy.
