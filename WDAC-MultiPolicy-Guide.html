Run everything in an elevated PowerShell session. On Server Core, type powershell at the cmd prompt.

0. Concepts

TermMeaning
Base policyA standalone policy with its own GUID. With several base policies active, a file must be allowed by all of them.
Supplemental policyAttached to one base policy by GUID. It adds allow rules, so it widens that base.
Active locationC:\Windows\System32\CodeIntegrity\CiPolicies\Active\{PolicyGUID}.cip
ToolsConfigCI PowerShell module (authoring) and CiTool.exe (deploy, list, remove). CiTool ships with Server 2025.

Lab layout:

  • P1: base policy, audit mode (based on DefaultWindows).
  • P2: supplemental policy for line-of-business apps, attached to P1.
  • P3: second base policy, "allow all except these blocked tools".

1. Prepare the working folder

$w = "C:\WDAC"
New-Item -ItemType Directory -Path $w\XML, $w\CIP, $w\Backup -Force
Get-Command -Module ConfigCI | Select-Object -First 5      # confirm the module exists
Get-Command CiTool.exe                                      # confirm CiTool exists
Get-ChildItem C:\Windows\schemas\CodeIntegrity\ExamplePolicies   # built-in templates
If ConfigCI is missing on Core, author the XML on a management machine and copy the .cip files over. Deployment only needs CiTool.exe.

2. Create the policies

P1: Base policy, audit mode

Copy-Item C:\Windows\schemas\CodeIntegrity\ExamplePolicies\DefaultWindows_Audit.xml $w\XML\P1-Base.xml

# Give it a new unique GUID and a name
Set-CIPolicyIdInfo -FilePath $w\XML\P1-Base.xml -PolicyName "P1-Base-Audit" -ResetPolicyID

# Allow supplemental policies (option 17) and update without reboot (option 16)
Set-RuleOption -FilePath $w\XML\P1-Base.xml -Option 17
Set-RuleOption -FilePath $w\XML\P1-Base.xml -Option 16

Option 3 (Audit Mode) is already set in the audit template. It logs violations but blocks nothing.

P2: Supplemental policy

$p1id = ([xml](Get-Content $w\XML\P1-Base.xml)).SiPolicy.BasePolicyID

New-CIPolicy -FilePath $w\XML\P2-Supp.xml -ScanPath C:\Apps -Level Publisher -Fallback Hash -UserPEs -MultiplePolicyFormat

# Make it a supplemental policy of P1
Set-CIPolicyIdInfo -FilePath $w\XML\P2-Supp.xml -PolicyName "P2-Supp-LOBApps" -SupplementsBasePolicyID $p1id -ResetPolicyID

-Level Publisher -Fallback Hash trusts the signer where there is one, and falls back to a file hash for unsigned files.

P3: Second base policy (allow all, deny specific tools)

Copy-Item C:\Windows\schemas\CodeIntegrity\ExamplePolicies\AllowAll.xml $w\XML\P3-Deny.xml
Set-CIPolicyIdInfo -FilePath $w\XML\P3-Deny.xml -PolicyName "P3-DenyTools" -ResetPolicyID

$deny = New-CIPolicyRule -DriverFilePath C:\Tools\badtool.exe -Level FileName -Deny
Merge-CIPolicy -PolicyPaths $w\XML\P3-Deny.xml -OutputFilePath $w\XML\P3-Deny.xml -Rules $deny
Set-RuleOption -FilePath $w\XML\P3-Deny.xml -Option 3     # audit first

3. Convert to binary (.cip)

Multiple-policy format requires the file name to be the policy GUID.

foreach ($n in "P1-Base","P2-Supp","P3-Deny") {
    $xml  = "$w\XML\$n.xml"
    $guid = ([xml](Get-Content $xml)).SiPolicy.PolicyID
    ConvertFrom-CIPolicy -XmlFilePath $xml -BinaryFilePath "$w\CIP\$guid.cip"
    "$n  ->  $guid"
}
Get-ChildItem $w\CIP

4. Deploy

# Back up currently active policies first
Copy-Item C:\Windows\System32\CodeIntegrity\CiPolicies\Active\*.cip $w\Backup -ErrorAction SilentlyContinue

# Deploy all (base policy before its supplemental)
Get-ChildItem $w\CIP\*.cip | ForEach-Object { CiTool.exe --update-policy $_.FullName }

# Apply without reboot (works because option 16 is set)
CiTool.exe --refresh

Manual alternative (no CiTool)

Copy-Item $w\CIP\*.cip C:\Windows\System32\CodeIntegrity\CiPolicies\Active\
Restart-Computer

Remote deployment

$servers = "SRV01","SRV02"
foreach ($s in $servers) {
    Copy-Item $w\CIP\*.cip "\\$s\C$\Windows\System32\CodeIntegrity\CiPolicies\Active\"
    Invoke-Command -ComputerName $s -ScriptBlock { CiTool.exe --refresh }
}

Domain-wide options are Intune/MDM (ApplicationControl CSP), Configuration Manager, or Group Policy. Group Policy supports a single policy file only.

5. View and verify

CiTool.exe --list-policies                       # ID, name, base or supplemental, enforced or audit
CiTool.exe --list-policies -json | ConvertFrom-Json
Get-ChildItem C:\Windows\System32\CodeIntegrity\CiPolicies\Active

# Enforcement status: 0 = off, 1 = audit, 2 = enforced
Get-CimInstance -ClassName Win32_DeviceGuard -Namespace root\Microsoft\Windows\DeviceGuard |
  Select-Object CodeIntegrityPolicyEnforcementStatus, UsermodeCodeIntegrityPolicyEnforcementStatus

# Audit and block events
Get-WinEvent -LogName "Microsoft-Windows-CodeIntegrity/Operational" -MaxEvents 50 |
  Where-Object Id -in 3076,3077,3099 | Format-Table TimeCreated, Id, Message -Wrap
Event IDMeaning
3099Policy loaded
3076Would have been blocked (audit mode)
3077Blocked (enforced)
3089Signature details for the file

6. Modify a policy

6a. Add rules learned from audit events

New-CIPolicy -Audit -FilePath $w\XML\audit-rules.xml -Level Publisher -Fallback Hash -UserPEs
Merge-CIPolicy -PolicyPaths $w\XML\P1-Base.xml, $w\XML\audit-rules.xml -OutputFilePath $w\XML\P1-Base.xml

For a supplemental policy, merge the rules into P2 instead, so P1 stays minimal.

6b. Add a path rule

$r = New-CIPolicyRule -FilePathRule "D:\Tools\*"
Merge-CIPolicy -PolicyPaths $w\XML\P2-Supp.xml -OutputFilePath $w\XML\P2-Supp.xml -Rules $r

Path rules are weaker than signer rules. Use them only on folders that only admins can write to.

6c. Change options

Set-RuleOption -FilePath $w\XML\P1-Base.xml -Option 3 -Delete   # remove audit mode: policy becomes ENFORCED
Set-RuleOption -FilePath $w\XML\P1-Base.xml -Option 3           # back to audit

6d. Bump version, rebuild, redeploy

Set-CIPolicyVersion -FilePath $w\XML\P1-Base.xml -Version "1.0.0.1"
$g = ([xml](Get-Content $w\XML\P1-Base.xml)).SiPolicy.PolicyID
ConvertFrom-CIPolicy $w\XML\P1-Base.xml "$w\CIP\$g.cip"
CiTool.exe --update-policy "$w\CIP\$g.cip"

Redeploying a policy with the same GUID replaces it in place.

7. Move to enforcement

  1. Run in audit mode for one to two weeks, covering reboots, patching and backups.
  2. Review the 3076 events and merge the valid ones (6a).
  3. Delete option 3 (6c), rebuild, bump the version, redeploy.
  4. Check that 3077 events are limited to what you intended to block.
Enforced WDAC puts PowerShell into Constrained Language Mode for scripts the policy doesn't allow. Test your admin scripts before enforcing.

8. Remove policies

# One policy by GUID (supplemental first, then base)
CiTool.exe --remove-policy "{GUID-of-P2}"
CiTool.exe --remove-policy "{GUID-of-P1}"

# Or manually, then reboot
Remove-Item "C:\Windows\System32\CodeIntegrity\CiPolicies\Active\{GUID}.cip"
Restart-Computer

# Remove everything deployed in this lab
Get-ChildItem $w\CIP\*.cip | ForEach-Object {
    CiTool.exe --remove-policy ("{" + $_.BaseName.Trim("{}") + "}")
}

Some policies only fully disappear after a reboot. Check with CiTool.exe -lp.

9. Rollback

Options, from least to most disruptive:

A. Flip back to audit (safest)

Set-RuleOption -FilePath $w\XML\P1-Base.xml -Option 3
Set-CIPolicyVersion -FilePath $w\XML\P1-Base.xml -Version "1.0.0.2"
$g = ([xml](Get-Content $w\XML\P1-Base.xml)).SiPolicy.PolicyID
ConvertFrom-CIPolicy $w\XML\P1-Base.xml "$w\CIP\$g.cip"
CiTool.exe --update-policy "$w\CIP\$g.cip"

B. Restore the previous version

Copy-Item $w\Backup\{GUID}.cip C:\Windows\System32\CodeIntegrity\CiPolicies\Active\ -Force
CiTool.exe --refresh

C. Remove the policy

See section 8.

D. Server won't boot or you're locked out

  • Boot into WinRE or Repair mode from the Windows Server install media, open a command prompt, and delete the file:
    del C:\Windows\System32\CodeIntegrity\CiPolicies\Active\{GUID}.cip
  • Delete only the offending GUID, not the whole folder.
  • This works for unsigned policies. A signed policy can't be deleted this way and must be replaced by a signed update, so don't use signing in a lab.

Safety net: timed auto-rollback

$a = New-ScheduledTaskAction -Execute "CiTool.exe" -Argument "--remove-policy {GUID}"
$t = New-ScheduledTaskTrigger -Once -At (Get-Date).AddMinutes(30)
Register-ScheduledTask -TaskName "WDAC-Rollback" -Action $a -Trigger $t -User SYSTEM -RunLevel Highest

# If everything works, cancel it:
Unregister-ScheduledTask -TaskName "WDAC-Rollback" -Confirm:$false
