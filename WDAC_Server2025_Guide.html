Study1. What's different on Windows Server 2025

TopicWindows Server 2025 behavior
CiToolIncluded (C:\Windows\System32\CiTool.exe). Use it to add, list and remove policies and to refresh. You don't need RefreshPolicy.exe or WMI.
OSConfig default policiesMicrosoft provides an unsigned AllowMicrosoft base and a BlockUMCI (app block list) for WS2025. You apply them with Set-OSConfigDesiredConfiguration. They are not applied by default.
Drift controlPolicies set through OSConfig are reapplied about every 4 hours if they are removed manually or with CiTool. Remove them through OSConfig.
Build requirementThe OSConfig policies need a production-signed Server 2025 build. Flight-signed (Insider) binaries can make the server unbootable.
Policy removalServer 2025 shares the Windows 11 24H2 codebase. Unsigned policies are removed with CiTool -rp without a restart.
Signed policy + memory integrityThe “reboot to activate new signed base policies with HVCI” known issue affects Windows 11 updates earlier than 24H2. On a 26100-based server it doesn't apply. Still, a reboot after deploying a signed base to EFI is the safe practice.
Server CoreNo Event Viewer or msinfo32 GUI: use Get-WinEvent and Win32_DeviceGuard. The AppLocker – MSI and Script event log is not on Server Core. Run the App Control Wizard on a client.
ManagementStandalone or lab: OSConfig / CiTool. Domain: GPO (single policy format only) or script via GPO startup / ConfigMgr. Hybrid: Azure Arc + Azure Monitor workbook for the events.

Study2. Core concepts

App Control for Business (formerly WDAC) is enforced by Code Integrity (CI) in the kernel. It controls kernel drivers (signing scenario 131) and, with option 0 Enabled:UMCI, user-mode code (signing scenario 12): EXE, DLL, MSI, scripts and packaged apps.

Rule precedence

1. Explicit Deny in any policy→ blocked 2. Explicit Allow→ 3. Managed Installer / ISG (if enabled)→ 4. No match = implicit deny

With several base policies active (for example, the OSConfig AllowMicrosoft base plus your deny policy), a file must be allowed by every base policy, together with that base's supplementals.

Policy types

  • Base: stands alone. Option 17 lets it accept supplementals.
  • Supplemental: adds allow rules to one base through BasePolicyID. Deny rules in a supplemental are ignored.
  • Deny (blocklist): a base with explicit deny rules plus “Allow All” rules.

Server 2025 file format

Multiple policy format only: binary {PolicyId}.cip in C:\Windows\System32\CodeIntegrity\CIPolicies\Active\. Up to 32 active policies is the classic limit. Newer builds raise it, but keep the count small.

Design4. Prepare the server

  1. Confirm the OS and build (production-signed 26100.x). 
    Get-ComputerInfo -Property OsName, OsVersion, OsBuildNumber, WindowsInstallationType
# OsName: Microsoft Windows Server 2025 Datacenter   OsBuildNumber: 26100
# WindowsInstallationType: Server  (Desktop Experience) | Server Core
Get-Command CiTool.exe
  2. Record the current App Control and VBS state. 
    Get-CimInstance -Namespace root\Microsoft\Windows\DeviceGuard -ClassName Win32_DeviceGuard |
  Select-Object CodeIntegrityPolicyEnforcementStatus, UsermodeCodeIntegrityPolicyEnforcementStatus,
                VirtualizationBasedSecurityStatus, SecurityServicesRunning
# Enforcement status: 0 = Off  1 = Audit  2 = Enforced
# SecurityServicesRunning contains 2 = memory integrity (HVCI) running
CiTool -lp

    A fresh server shows only Microsoft platform policies, such as Microsoft Windows Driver Policy (d2bda982-…).

  3. Install the OSConfig module (for Track A): 
    Install-Module -Name Microsoft.OSConfig -Scope AllUsers -Repository PSGallery -Force
Get-Module -ListAvailable -Name Microsoft.OSConfig
  4. Create the working folder and check the ConfigCI cmdlets (for Track B): 
    New-Item -ItemType Directory -Path C:\WDAC -Force
Get-Command -Module ConfigCI | Select-Object Name
Get-ChildItem "$env:windir\schemas\CodeIntegrity\ExamplePolicies"
  5. Inventory the server workload. Third-party agents (backup, monitoring, AV), drivers and scheduled-task scripts are what will break. 
    Get-WindowsFeature | Where-Object Installed | Select-Object Name
Get-Package | Where-Object ProviderName -eq Programs | Select-Object Name, Version
Get-CimInstance Win32_SystemDriver | Where-Object State -eq Running |
  Select-Object Name, PathName | Sort-Object PathName
Get-ScheduledTask | Where-Object State -ne Disabled |
  Select-Object TaskPath, TaskName, @{n="Exec";e={$_.Actions.Execute}}
  6. Back up: create a VM checkpoint and escrow the BitLocker recovery key if BitLocker is on.

Design5. Choose a track and design the policy set

Track A: OSConfig default policies

Microsoft-built AllowMicrosoft_WS2025 base + BlockUMCI_Microsoft_WS2025 block list. You add supplementals for third-party apps. Drift-controlled.

Best for: fast, supported baseline on standalone or Arc-managed servers.

Track B: Custom ConfigCI policies + CiTool

Your own base, supplemental and deny policies built with PowerShell, deployed with CiTool or by your tooling. Full control, and can be signed.

Best for: custom requirements, signed policies, or training on how policies work.

You can combine them: Track A for the allowlist plus a Track B deny base for extra blocks. Supplementals for Track A must point at base {9214D8EE-9B0F-4972-9073-A04E917D7989} and be applied through OSConfig.

Track AA1. Apply the Microsoft default policies (audit)

Production-signed Server 2025 build only. Flight-signed binaries can leave the server unable to start.
  1. Apply in audit mode (elevated PowerShell): 
    Set-OSConfigDesiredConfiguration -Scenario AppControl\WS2025\DefaultPolicy\Audit -Default
Set-OSConfigDesiredConfiguration -Scenario AppControl\WS2025\AppBlockList\Audit -Default
  2. Verify: 
    citool -lp | findstr /I "WS2025"
# Expected:
# Friendly Name: BlockUMCI_Microsoft_WS2025_Audit
# Friendly Name: AllowMicrosoft_WS2025_Audit
  3. Generate activity: run the backup job, open 7-Zip, run admin scripts, apply the monthly CU. Then look for 3076 events (section 6).

Track AA2. Build a supplemental policy from audit events

  1. Export the audit events to .evtx. You can use Event Viewer (Filter Current Log → 3076 → Save Filtered Log File As), or on Server Core: 
    wevtutil epl "Microsoft-Windows-CodeIntegrity/Operational" C:\WDAC\SRV-APP01_3076.evtx /q:"*[System[(EventID=3076)]]"
  2. Copy the .evtx file to WKS-ADM01 (Windows 10 1909+ with the App Control Wizard, which needs .NET Desktop Runtime 8.0+).
  3. In the Wizard: Policy Editor → Convert Event Logs to a Policy → Parse Log File(s) → select the .evtx → Next.
  4. On File Rules, select each file → Rule Type (Microsoft's walkthrough uses Path. Publisher is stronger for signed files) → + Add Allow → Next. The XML is saved to C:\Users\<user>\Documents.
  5. Copy the XML to the server and apply it through OSConfig: 
    $policyPath = "C:\WDAC\Contoso_Supp_7Zip.xml"

# Reset GUID (best practice)
Set-CIPolicyIdInfo -FilePath $policyPath -ResetPolicyID

# Set policy version (VersionEx in the XML file)
$policyVersion = "1.0.0.1"
Set-CIPolicyVersion -FilePath $policyPath -Version $policyVersion

# Set policy info (PolicyName and the PolicyID setting string in the XML file)
Set-CIPolicyIdInfo -FilePath $policyPath -PolicyID "7Zip-Policy_$policyVersion" -PolicyName "7Zip-Policy"

# Link to the OSConfig WS2025 base policy
$base = "{9214D8EE-9B0F-4972-9073-A04E917D7989}"
Set-CIPolicyIdInfo -FilePath $policyPath -SupplementsBasePolicyID $base

# Set the new policy into the system
Set-OSConfigDesiredConfiguration -Scenario AppControl -Name Policies -Value $policyPath
  6. Verify: run the app again and confirm that no new 3076 events appear for it.

Track AA3. Enforce, query and remove the OSConfig policies

Switch to enforcement

# Remove the audit versions first, then apply the enforce versions
Remove-OSConfigDesiredConfiguration -Scenario AppControl\WS2025\DefaultPolicy\Audit
Remove-OSConfigDesiredConfiguration -Scenario AppControl\WS2025\AppBlockList\Audit

Set-OSConfigDesiredConfiguration -Scenario AppControl\WS2025\DefaultPolicy\Enforce -Default
Set-OSConfigDesiredConfiguration -Scenario AppControl\WS2025\AppBlockList\Enforce -Default

citool -lp | findstr /I "WS2025"
# Friendly Name: BlockUMCI_Microsoft_WS2025_Enforce
# Friendly Name: AllowMicrosoft_WS2025_Enforce

Query effective and inactive policies

# Effective
(Get-OSConfigDesiredConfiguration -Scenario AppControl).Value.PSObject.Properties |
  ForEach-Object { $_.Value.PolicyInfo } | Where-Object { $_.IsEffective -eq $true }

# Inactive
(Get-OSConfigDesiredConfiguration -Scenario AppControl).Value.PSObject.Properties |
  ForEach-Object { $_.Value.PolicyInfo } | Where-Object { $_.IsEffective -eq $false }

Remove

Remove-OSConfigDesiredConfiguration -Scenario AppControl\WS2025\DefaultPolicy\Enforce
Remove-OSConfigDesiredConfiguration -Scenario AppControl\WS2025\AppBlockList\Enforce

Track BB1. Create a custom base policy (audit)

  1. Start from AllowMicrosoft (the recommended server baseline): 
    $Base = "C:\WDAC\Contoso_SRV_Base.xml"
Copy-Item "$env:windir\schemas\CodeIntegrity\ExamplePolicies\AllowMicrosoft.xml" $Base

$x.SiPolicy | Select-Object PolicyID, BasePolicyID, VersionEx, PolicyType
$x.SiPolicy.Rules.Rule.Option

Track BB2. Supplemental policy for third-party software

$Supp = "C:\WDAC\Contoso_Supp_7Zip.xml"
New-CIPolicy -FilePath $Supp -ScanPath "C:\Program Files\7-Zip" `
  -Level FilePublisher -Fallback SignedVersion,Hash -UserPEs -MultiplePolicyFormat

Set-CIPolicyIdInfo -FilePath $Supp -PolicyName "Contoso Supp - 7-Zip" `
  -SupplementsBasePolicyID "{3C9F8E21-7B4D-4A6E-9F12-6D8E5A0B47C3}"
Set-CIPolicyIdInfo -FilePath $Supp -ResetPolicyID      # -> {8E4A2D17-...}
Set-RuleOption     -FilePath $Supp -Option 6

# Repeat for the backup agent, for example:
New-CIPolicy -FilePath C:\WDAC\Contoso_Supp_Backup.xml -ScanPath "C:\Program Files\Contoso Backup Agent" `
  -Level FilePublisher -Fallback SignedVersion,Hash -UserPEs -MultiplePolicyFormat

Track BB3. Deny policy (blocklist)

A deny-only base must include Allow All rules for kernel mode (131) and user mode (12). Without them, everything else is implicitly denied. If you already apply the OSConfig AppBlockList, add only the blocks it doesn't cover.

Build the deny rules

$DenyRules = @()

# Publisher-based (recommended for signed files)
$DenyRules += New-CIPolicyRule -Level FilePublisher -DriverFilePath "C:\Windows\System32\mshta.exe" `
  -Fallback SignedVersion,Publisher,Hash -Deny

# Attribute-based (OriginalFileName)
$DenyRules += New-CIPolicyRule -Level FileName -DriverFilePath "C:\Tools\MaliciousApp.exe" -Fallback Hash -Deny

# Hash-based – only when necessary
$DenyRules += New-CIPolicyRule -Level Hash -DriverFilePath "C:\Tools\MaliciousApp.exe" -Deny

Merge with AllowAll

$DenyPolicy     = "C:\WDAC\Contoso_SRV_Deny.xml"
$AllowAllPolicy = $Env:windir + "\schemas\CodeIntegrity\ExamplePolicies\AllowAll.xml"
Merge-CIPolicy -PolicyPaths $AllowAllPolicy -OutputFilePath $DenyPolicy -Rules $DenyRules
Set-CiPolicyIdInfo -FilePath $DenyPolicy -PolicyName "Contoso SRV Deny" -ResetPolicyID
Set-RuleOption -FilePath $DenyPolicy -Option 3
Set-RuleOption -FilePath $DenyPolicy -Option 16

Allow All rules (from AllowAll.xml)

<FileRules>
  <Allow ID="ID_ALLOW_A_1" FriendlyName="Allow Kernel Drivers" FileName="*" />
  <Allow ID="ID_ALLOW_A_2" FriendlyName="Allow User mode components" FileName="*" />
</FileRules>
<SigningScenarios>
  <SigningScenario Value="131" ID="ID_SIGNINGSCENARIO_DRIVERS" FriendlyName="Kernel Mode Signing Scenario">
    <ProductSigners><FileRulesRef><FileRuleRef RuleID="ID_ALLOW_A_1" /></FileRulesRef></ProductSigners>
  </SigningScenario>
  <SigningScenario Value="12" ID="ID_SIGNINGSCENARIO_WINDOWS" FriendlyName="User Mode Signing Scenario">
    <ProductSigners><FileRulesRef><FileRuleRef RuleID="ID_ALLOW_A_2" /></FileRulesRef></ProductSigners>
  </SigningScenario>
</SigningScenarios>

Or merge into an existing allowlist (no Allow All)

$DenyPolicy     = "C:\WDAC\Contoso_SRV_Deny.xml"
$ExistingPolicy = "C:\WDAC\Contoso_SRV_Base.xml"
Merge-CIPolicy -PolicyPaths $DenyPolicy, $ExistingPolicy -OutputFilePath $ExistingPolicy

Track BB4. Convert and deploy with CiTool

Convert XML → {PolicyId}.cip

foreach ($xml in "Contoso_SRV_Base.xml","Contoso_Supp_7Zip.xml","Contoso_SRV_Deny.xml") {
  $path = "C:\WDAC\$xml"
  $id   = ([xml](Get-Content $path)).SiPolicy.PolicyID
  ConvertFrom-CIPolicy -XmlFilePath $path -BinaryFilePath "C:\WDAC\$id.cip"
}
Get-ChildItem C:\WDAC\*.cip

Deploy (base first, then supplemental, then deny)

CiTool --update-policy "C:\WDAC\{3C9F8E21-7B4D-4A6E-9F12-6D8E5A0B47C3}.cip" -json
CiTool --update-policy "C:\WDAC\{8E4A2D17-C6B5-4F09-A3D1-2B7E9C40F615}.cip" -json
CiTool --update-policy "C:\WDAC\{D2F7C9B1-5A3E-4C8D-B6F0-91E4A7C2D358}.cip" -json

# Only the enforced/active ones
(CiTool -lp -json | ConvertFrom-Json).Policies | Where-Object {$_.IsEnforced -eq "True"} |
  Select-Object -Property PolicyID,FriendlyName | Format-List

Deploy to many servers (PowerShell remoting)

$servers = "SRV-APP01","SRV-APP02","SRV-WEB01"
foreach ($s in $servers) {
  Copy-Item C:\WDAC\*.cip -Destination "\\$s\C$\Windows\Temp\" -Force
}
Invoke-Command -ComputerName $servers -ScriptBlock {
  Get-ChildItem C:\Windows\Temp\*.cip | ForEach-Object { CiTool --update-policy $_.FullName -json }
}

Verify activation

Get-WinEvent -LogName "Microsoft-Windows-CodeIntegrity/Operational" -MaxEvents 50 |
  Where-Object Id -in 3099,3101,3102,3095,3097,3100 | Format-Table TimeCreated, Id, Message -Wrap

Expected: 3101 → 3099 (one per policy, with its options) → 3102. If you see 3095, a reboot is required.

Operate7. Switch from audit to enforce (Track B)

  1. Make sure there are no unexplained 3076/8028 events after a full cycle (patching, backups, scheduled tasks, reboot).
  2. Remove audit mode and raise the version. Keep the same PolicyId. 
    $E = "C:\WDAC\Contoso_SRV_Base.xml"
Set-RuleOption -FilePath $E -Option 3 -Delete
Set-RuleOption -FilePath $E -Option 9 -Delete
Set-CIPolicyVersion -FilePath $E -Version "1.0.1.0"
ConvertFrom-CIPolicy -XmlFilePath $E -BinaryFilePath "C:\WDAC\{3C9F8E21-7B4D-4A6E-9F12-6D8E5A0B47C3}.cip"
CiTool --update-policy "C:\WDAC\{3C9F8E21-7B4D-4A6E-9F12-6D8E5A0B47C3}.cip" -json
  3. Test: mshta.exe should fail with event 3077. $ExecutionContext.SessionState.LanguageMode should return ConstrainedLanguage for unsigned interactive sessions under enforced UMCI.
  4. Rings: lab → non-critical servers → one server per role → all servers.

Operate8. Update and maintain

  • New app: add a supplemental policy. Track A: Set-OSConfigDesiredConfiguration -Scenario AppControl -Name Policies -Value. Track B: CiTool -up.
  • Change a policy: keep the PolicyId, raise VersionEx, convert and redeploy. A lower version is rejected.
  • Agent upgrades: FilePublisher rules with a minimum version survive upgrades. Hash rules don't.
  • Monthly CU: Windows-signed files are already trusted, but test in audit after each CU on a pilot server.
  • Source control: keep the XML in Git. The .cip file is a build output.
  • Driver blocklist: Microsoft Windows Driver Policy (d2bda982-…) is serviced by Windows Update. Keep it.

Operate9. Signed policies (Track B, tamper protection)

You can't remove a signed base policy by simply deleting it. That causes a boot failure. Rehearse section 10e in the lab first.
  1. Add signers and remove option 6: 
    $P = "C:\WDAC\Contoso_SRV_Base.xml"
Add-SignerRule -FilePath $P -CertificatePath C:\WDAC\Certs\ContosoAppControlSigner.cer -Update
Add-SignerRule -FilePath $P -CertificatePath C:\WDAC\Certs\ContosoAppControlSigner.cer -Supplemental
Set-RuleOption -FilePath $P -Option 6 -Delete
Set-CIPolicyVersion -FilePath $P -Version "1.1.0.0"
ConvertFrom-CIPolicy -XmlFilePath $P -BinaryFilePath "C:\WDAC\{3C9F8E21-7B4D-4A6E-9F12-6D8E5A0B47C3}.cip"
  2. Sign it (signtool comes with the Windows SDK, so run it on the admin workstation): 
    signtool.exe sign -v -n "Contoso App Control Signer" -p7 C:\WDAC\Signed -p7co 1.3.6.1.4.1.311.79.1 -fd sha256 `
  "C:\WDAC\{3C9F8E21-7B4D-4A6E-9F12-6D8E5A0B47C3}.cip"
# Rename the output {GUID}.cip.p7 -> {GUID}.cip
  3. Deploy to the EFI partition and reboot: 
    $PolicyBinary         = "C:\WDAC\Signed\{3C9F8E21-7B4D-4A6E-9F12-6D8E5A0B47C3}.cip"
$MountPoint           = 'C:\EFIMount'
$EFIDestinationFolder = "$MountPoint\EFI\Microsoft\Boot\CiPolicies\Active"
$EFIPartition = (Get-Partition | Where-Object IsSystem).AccessPaths[0]
if (-Not (Test-Path $MountPoint)) { New-Item -Path $MountPoint -Type Directory -Force }
mountvol $MountPoint $EFIPartition
if (-Not (Test-Path $EFIDestinationFolder)) { New-Item -Path $EFIDestinationFolder -Type Directory -Force }
Copy-Item -Path $PolicyBinary -Destination $EFIDestinationFolder -Force
mountvol $MountPoint /D
CiTool --update-policy $PolicyBinary -json
Restart-Computer
  4. Check: CiTool -lp → “Policy is Signed: true”, “Is Currently Enforced: true”.

Operate10. Remove or disable policies

First stop the method that deploys the policy (OSConfig, GPO, ConfigMgr, remoting script). Otherwise it comes back. For OSConfig policies, see A3.

10a. Neutralize first (optional)

Redeploy the policy (same PolicyId, higher version) with: Allow * rules · option 3 Audit · option 11 Disabled:Script Enforcement · all COM objects allowed · option 0 removed if needed.

10b. CiTool (unsigned, no restart needed on Server 2025)

CiTool.exe -rp "{D2F7C9B1-5A3E-4C8D-B6F0-91E4A7C2D358}" -json   # deny
CiTool.exe -rp "{8E4A2D17-C6B5-4F09-A3D1-2B7E9C40F615}" -json   # supplemental
CiTool.exe -rp "{3C9F8E21-7B4D-4A6E-9F12-6D8E5A0B47C3}" -json   # base
CiTool -lp

10c. Script (removes the files, then restart)

# Run as Administrator
$PolicyId = "{3C9F8E21-7B4D-4A6E-9F12-6D8E5A0B47C3}"

$SinglePolicyFormatPolicyId = "{A244370E-44C9-4C06-B551-F6016E563076}"
$SinglePolicyFormatFileName = "\SiPolicy.p7b"
$MountPoint =  $env:SystemDrive+"\EFIMount"
$SystemCodeIntegrityFolderRoot = $env:windir+"\System32\CodeIntegrity"
$EFICodeIntegrityFolderRoot = $MountPoint+"\EFI\Microsoft\Boot"
$MultiplePolicyFilePath = "\CiPolicies\Active\"+$PolicyId+".cip"

$EFIPartition = (Get-Partition | Where-Object IsSystem).AccessPaths[0]
if (-Not (Test-Path $MountPoint)) { New-Item -Path $MountPoint -Type Directory -Force }
mountvol $MountPoint $EFIPartition

if ($PolicyId -eq $SinglePolicyFormatPolicyId) {$NumFilesToDelete = 4} else {$NumFilesToDelete = 2}
$Count = 1
while ($Count -le $NumFilesToDelete) {
    Switch ($Count) {
        1 {$PolicyPath = $SystemCodeIntegrityFolderRoot+$MultiplePolicyFilePath}
        2 {$PolicyPath = $EFICodeIntegrityFolderRoot+$MultiplePolicyFilePath}
        3 {$PolicyPath = $SystemCodeIntegrityFolderRoot+$SinglePolicyFormatFileName}
        4 {$PolicyPath = $EFICodeIntegrityFolderRoot+$SinglePolicyFormatFileName}
    }
    Write-Host "Attempting to remove $PolicyPath..." -ForegroundColor Cyan
    if (Test-Path $PolicyPath) {Remove-Item -Path $PolicyPath -Force -ErrorAction Continue}
    $Count = $Count + 1
}
mountvol $MountPoint /D
Restart-Computer

10d. Group Policy / MDM

GPO: set Computer Configuration → Administrative Templates → System → Device Guard → Deploy App Control for Business to Disabled or Not configured, then delete the policy file and restart. MDM: remove it through the ApplicationControl CSP, then restart.

10e. Removing a signed base policy (strict order)

  1. Create a replacement with the same PolicyId, a version that is equal or higher, <UpdatePolicySigners> kept, and option 6 added: 
    $P = "C:\WDAC\Contoso_SRV_Base.xml"
Set-RuleOption -FilePath $P -Option 6
Set-CIPolicyVersion -FilePath $P -Version "1.2.0.0"
ConvertFrom-CIPolicy -XmlFilePath $P -BinaryFilePath "C:\WDAC\{3C9F8E21-7B4D-4A6E-9F12-6D8E5A0B47C3}.cip"
  2. Sign it with a certificate listed in the original <UpdatePolicySigners>.
  3. Deploy it to System32 and EFI, then restart. This turns off UEFI protection. If you skip this restart, the server fails to boot.
  4. Remove the policy (10b or 10c) and restart.

Signed supplemental policies are removed like unsigned ones.

Operate11. Recover from boot stop failures

To prevent this, set option 10 Enabled:Boot Audit On Failure. If the server still won't boot:

  1. Signed policy: turn off Secure Boot. For a Hyper-V Gen2 VM: Set-VMFirmware -VMName SRV-APP01 -EnableSecureBoot Off. For physical hardware, use the OEM UEFI setup (iLO/iDRAC console).
  2. Advanced Boot Options → Disable Driver Signature Enforcement. This suspends CI, including App Control, for one boot.
  3. Sign in and run the removal script (10c).
  4. If BitLocker is on: Suspend-BitLocker -MountPoint C: -RebootCount 1, then turn Secure Boot back on (Set-VMFirmware -VMName SRV-APP01 -EnableSecureBoot On).
  5. Restart.
Have the BitLocker recovery key ready: (Get-BitLockerVolume C:).KeyProtector | Where-Object KeyProtectorType -eq RecoveryPassword. On a domain, it may be escrowed in AD DS.

RefChecklists

Before enforcing on a server

  • ☐ Production-signed Server 2025 build (26100), not flight-signed
  • ☐ Base policy has options 0, 4, 10, 16, 17 (and 6 while unsigned), or OSConfig DefaultPolicy is used
  • ☐ Audit ran through a full cycle: CU install, reboot, backup, scheduled tasks
  • ☐ Supplementals exist for every agent, including their kernel drivers
  • ☐ Deny policy has the Allow All rules
  • ☐ VersionEx raised, binary named {PolicyId}.cip
  • ☐ Rollback tested: CiTool -rp / Remove-OSConfigDesiredConfiguration
  • ☐ VM checkpoint / BitLocker key available; console (iLO/iDRAC/Hyper-V) access confirmed
