Windows Defender Application Control (WDAC)

Policy structure, discovery, modification, rules, backup and rollback — with diagrams and PowerShell.

Before you start. Run all commands in an elevated PowerShell on a lab VM with a snapshot. The ConfigCI cmdlets (New-CIPolicy, Merge-CIPolicy, …) are available on Windows 10/11 and Windows Server. CiTool.exe is built into Windows 11 22H2+ and Windows Server 2025; on Windows 10 and Server 2016–2022 use the file-based equivalents shown alongside.
Windows Server 2025. This guide applies directly: use the CiTool commands as the primary method (list, update, remove), with the file-copy method as a fallback. Microsoft now brands WDAC as App Control for Business — the tooling, XML and cmdlets are unchanged. The sample policies are in C:\Windows\schemas\CodeIntegrity\ExamplePolicies\; the file list in section 2D was confirmed on a Server 2025 VM. On Server, test with your server roles and management tools in audit mode first — blocking an admin tool or role binary on a production server is far costlier than on a workstation.

1Policy structure

A WDAC policy is an XML document that is compiled into a binary (.cip) and enforced by the kernel Code Integrity engine.

XML anatomy

XML
<SiPolicy xmlns="urn:schemas-microsoft-com:sipolicy" PolicyType="Base Policy">
  <VersionEx>10.0.0.0</VersionEx>
  <PlatformID>{2E07F7E4-194C-4D20-B7C9-6F44A6C5A234}</PlatformID>
  <PolicyID>{11111111-2222-3333-4444-555555555555}</PolicyID>
  <BasePolicyID>{11111111-2222-3333-4444-555555555555}</BasePolicyID>   <!-- same as PolicyID for a base -->

  <Rules>                                    <!-- policy OPTIONS -->
    <Rule><Option>Enabled:Unsigned System Integrity Policy</Option></Rule>
    <Rule><Option>Enabled:Audit Mode</Option></Rule>
    <Rule><Option>Enabled:UMCI</Option></Rule>
  </Rules>

  <EKUs />

  <FileRules>                                <!-- FILE rules -->
    <Allow ID="ID_ALLOW_A_1" FriendlyName="Tool hash" Hash="9F86D0..." />
    <Deny  ID="ID_DENY_B_1"  FriendlyName="Block bad.exe" FileName="bad.exe" MinimumFileVersion="65535.65535.65535.65535" />
  </FileRules>

  <Signers>                                  <!-- PUBLISHER rules -->
    <Signer ID="ID_SIGNER_MS_1" Name="Microsoft Code Signing PCA">
      <CertRoot Type="TBS" Value="A1B2C3..." />
      <CertPublisher Value="Microsoft Corporation" />
    </Signer>
  </Signers>

  <SigningScenarios>
    <SigningScenario Value="131" ID="ID_SS_KERNEL" FriendlyName="Kernel mode">
      <ProductSigners />
    </SigningScenario>
    <SigningScenario Value="12" ID="ID_SS_USER" FriendlyName="User mode">
      <ProductSigners>
        <AllowedSigners><AllowedSigner SignerId="ID_SIGNER_MS_1" /></AllowedSigners>
        <FileRulesRef>
          <FileRuleRef RuleID="ID_ALLOW_A_1" />
          <FileRuleRef RuleID="ID_DENY_B_1" />
        </FileRulesRef>
      </ProductSigners>
    </SigningScenario>
  </SigningScenarios>

  <UpdatePolicySigners />
  <HvciOptions>0</HvciOptions>
  <Settings />
</SiPolicy>
ElementPurpose
VersionExPolicy version (a.b.c.d). A replacement policy must carry a version higher than the one deployed, especially for signed policies.
PolicyID / BasePolicyIDGUID identity. Base: both equal. Supplemental: BasePolicyID points to the base it extends.
PlatformIDConstant schema/platform GUID – leave as generated.
RulesPolicy options (audit mode, UMCI, managed installer …). Not the same as file rules.
FileRulesAllow, Deny and FileAttrib entries for hash, file name, path, version.
SignersCertificate-based rules (Publisher, PCA, Root, WHQL …).
SigningScenariosValue 131 = kernel mode (drivers), 12 = user mode (apps/DLLs/scripts).
UpdatePolicySigners / CiSignersWho may update a signed policy / which signers are trusted by Code Integrity.
HvciOptionsMemory-integrity related flags (e.g. strict kernel-mode enforcement).
SettingsCustom key-value settings consumed by apps (e.g. via Set-CIPolicySetting).

Inspect any policy from PowerShell:

$p.SiPolicy.PolicyID

Base vs. supplemental policies

TypeUse caseNotes
BaseCore allow-list (e.g. Windows + Microsoft + Store, or Allow-all + block rules).Defines options. Needs option 17 Allow Supplemental Policies to be extendable.
SupplementalDepartment/app-specific additions without touching the base.Inherits options from base; only adds Allow rules.
Legacy single-policyOlder OS builds.One SiPolicy.p7b only; no supplementals.
PowerShell
# Create a new base policy from a built-in template, with a fresh GUID
Copy-Item C:\Windows\schemas\CodeIntegrity\ExamplePolicies\DefaultWindows_Audit.xml C:\WDAC\Base.xml
Set-CIPolicyIdInfo -FilePath C:\WDAC\Base.xml -PolicyName "Corp-Base" -ResetPolicyID
Set-RuleOption -FilePath C:\WDAC\Base.xml -Option 17      # allow supplemental policies

# Create a supplemental policy for that base
$baseId = (Get-CIPolicyIdInfo -FilePath C:\WDAC\Base.xml).BasePolicyID   # or read from XML
New-CIPolicy -FilePath C:\WDAC\Supp-HR.xml -ScanPath "C:\Program Files\HRApp" -Level FilePublisher -Fallback Hash -UserPEs -MultiplePolicyFormat
Set-CIPolicyIdInfo -FilePath C:\WDAC\Supp-HR.xml -SupplementsBasePolicyID $baseId -BasePolicyToSupplementPath C:\WDAC\Base.xml -PolicyName "Corp-HR-Supp" -ResetPolicyID

2Find existing policies & their use cases

Three places to look: the live system, the policy files on disk, and the built-in sample policies.

A. What is active on this machine?

PowerShell
# Windows 11 22H2+ / Server 2025 – the easy way
CiTool.exe --list-policies
CiTool.exe -lp -json | ConvertFrom-Json | Select -Expand Policies |
    Select PolicyID, FriendlyName, IsEnforced, IsSystemPolicy, IsSignedPolicy, Version

# Any build: enforcement state of Code Integrity
Get-CimInstance -ClassName Win32_DeviceGuard -Namespace root\Microsoft\Windows\DeviceGuard |
    Select CodeIntegrityPolicyEnforcementStatus, UsermodeCodeIntegrityPolicyEnforcementStatus
#   0 = Off   1 = Audit   2 = Enforced

# Any build: list the deployed binaries (multiple-policy format)
Get-ChildItem "$env:windir\System32\CodeIntegrity\CiPolicies\Active\*.cip" |
    Select Name, Length, LastWriteTime

# Legacy single-policy file?
Test-Path "$env:windir\System32\CodeIntegrity\SiPolicy.p7b"

B. Policies in the EFI system partition

PowerShell
mountvol Y: /S                                   # mount the EFI System Partition as Y:
Get-ChildItem Y:\EFI\Microsoft\Boot\CiPolicies\Active -ErrorAction SilentlyContinue
Get-ChildItem Y:\EFI\Microsoft\Boot\SiPolicy.p7b      -ErrorAction SilentlyContinue
mountvol Y: /D                                   # always unmount afterwards

C. What did the policy load / block? (event log)

PowerShell
# 3099 = policy loaded (shows policy name, GUID, version, options)
Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-CodeIntegrity/Operational'; Id=3099} -MaxEvents 10 |
    Format-List TimeCreated, Message

# 3076 = would-have-blocked (AUDIT)   3077 = blocked (ENFORCED)
Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-CodeIntegrity/Operational'; Id=3076,3077} -MaxEvents 50 |
    Select TimeCreated, Id, @{n='Detail';e={($_.Message -split "`n")[0]}}

# Scripts / MSI (AppLocker channel): 8028 audit, 8029 enforced
Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-AppLocker/MSI and Script'; Id=8028,8029} -MaxEvents 20

D. Built-in sample policies & use cases

PowerShell
Get-ChildItem C:\Windows\schemas\CodeIntegrity\ExamplePolicies\*.xml |

     $x = [xml](Get-Content $_.FullName)

Sample policyUse case
AllowAll.xmlStarting point when you only want to block specific things (add deny rules) – everything else runs.
AllowAll_EnableHVCI.xmlAllow everything but turn on memory integrity (HVCI) enforcement.
AllowMicrosoft.xmlAllow only Microsoft-signed code (Windows, Office, MS apps) – "Microsoft only" workstation.
DefaultWindows_Audit.xmlBest lab starting point. Windows + Store apps + WHQL drivers, in audit mode; add your own apps via scan.
DefaultWindows_Enforced.xmlSame as above, enforced – use when everything is already validated.
DefaultWindows_Supplemental.xmlTemplate supplemental policy to extend a DefaultWindows base with extra apps (base needs option 17).
DenyAllAudit.xmlAudit-only policy that flags every binary – used to inventory what runs on a machine.
RecommendedDriverBlock_Enforced.xmlMicrosoft's vulnerable-driver blocklist (~530 KB). Deploy as its own policy or merge into a base to block known-bad kernel drivers.
SmartAppControl.xmlThe Smart App Control policy (reputation-based, client-focused). Reference only – not normally used on servers.
Verified on Windows Server 2025 lab VM: the nine files above are exactly what ships in ExamplePolicies. Microsoft's Recommended block rules (user-mode LOLBins) are not in this folder – download them from Microsoft Learn and merge them into your base. System policies appear with IsSystemPolicy = True in CiTool.

3How to modify policies

Never edit the deployed .cip. Always edit the source XML, bump the version, recompile and redeploy.

Modification recipes

PowerShell
$xml = "C:\WDAC\Base.xml"

# 0. Safety copy
Copy-Item $xml "C:\WDAC\Backup\Base_$(Get-Date -f yyyyMMdd_HHmmss).xml"

# 1. Switch Audit -> Enforced  (delete option 3) / Enforced -> Audit (add option 3)
Set-RuleOption -FilePath $xml -Option 3 -Delete       # ENFORCE
Set-RuleOption -FilePath $xml -Option 3               # back to AUDIT

# 2. Merge in another policy's rules (e.g. Microsoft block rules, or an app scan)
New-CIPolicy -FilePath C:\WDAC\NewApp.xml -ScanPath "C:\Program Files\NewApp" `
             -Level FilePublisher -Fallback Hash -UserPEs
Merge-CIPolicy -PolicyPaths $xml, C:\WDAC\NewApp.xml -OutputFilePath $xml

# 3. Build rules from audit events (3076) instead of scanning
New-CIPolicy -FilePath C:\WDAC\FromAudit.xml -Audit -Level FilePublisher -Fallback Hash -UserPEs
Merge-CIPolicy -PolicyPaths $xml, C:\WDAC\FromAudit.xml -OutputFilePath $xml

# 4. Bump version (required for a replacement to take effect)
$v = [version](Get-CIPolicyInfo -FilePath $xml -ErrorAction SilentlyContinue).Version
if (-not $v) { $v = [version]([xml](Get-Content $xml)).SiPolicy.VersionEx }
Set-CIPolicyVersion -FilePath $xml -Version ([version]::new($v.Major,$v.Minor,$v.Build,$v.Revision+1))

# 5. Rename / re-identify
Set-CIPolicyIdInfo -FilePath $xml -PolicyName "Corp-Base v2"

# 6. Compile to binary (multiple-policy format; file name MUST be {PolicyID}.cip)
$id  = ([xml](Get-Content $xml)).SiPolicy.PolicyID
ConvertFrom-CIPolicy -XmlFilePath $xml -BinaryFilePath "C:\WDAC\Out\$id.cip"

Deploy the updated policy

MethodCommand / action
Windows 11 22H2+CiTool.exe --update-policy C:\WDAC\Out\{GUID}.cip (no reboot needed for most updates)
File copy (all builds)Copy-Item C:\WDAC\Out\{GUID}.cip "$env:windir\System32\CodeIntegrity\CiPolicies\Active\" then reboot (or use Microsoft's RefreshPolicy.exe)
IntuneEndpoint security → App Control for Business, or custom OMA-URI ./Vendor/MSFT/ApplicationControl/Policies/{GUID}/Policy (base64 .cip)
Group PolicyComputer Config → Admin Templates → System → Device Guard → Deploy Windows Defender Application Control (single-policy path)
Configuration ManagerEndpoint Protection → App Control for Business policies
Version rule. If you redeploy the same PolicyID with an equal or lower version, the update is ignored/rejected. Always increment VersionEx.
Tip. Add policy option 16 – Update Policy No Reboot to the base so later updates apply without restarting.

GUI alternative

The WDAC Wizard (Microsoft) can open any XML, edit rules and options, merge policies, and convert to binary – good for beginners in the lab.

4Rules: types, add, modify, remove

WDAC has two different things that people call "rules": policy rule options (behaviour switches) and file rules (what is allowed or denied).

Policy rule options
Stored in <Rules>. Control how the policy behaves – audit vs enforce, scripts, managed installer, supplemental support …
File rules
Stored in <FileRules> and <Signers>. Control which binaries are allowed or denied – by hash, publisher, name, path …

A. Policy rule options

#OptionMeaning
0Enabled:UMCIEnforce user-mode (apps/DLLs), not only drivers.
1Enabled:Boot Menu ProtectionHide F8 boot options when policy enforced.
2Required:WHQLDrivers must be WHQL-signed.
3Enabled:Audit Mode (Default)Log only, do not block. Remove to enforce.
4Disabled:Flight SigningDon't trust Insider/flight-signed builds.
5Enabled:Inherit Default PolicyReserved.
6Enabled:Unsigned System Integrity PolicyPolicy need not be signed (default for lab; removable by deleting the file).
7Allowed:Debug Policy AugmentedAllow debug-policy augmentation.
8Required:EV SignersDrivers must be EV signed.
9Enabled:Advanced Boot Options MenuAllow F8 menu – safety net during pilots.
10Enabled:Boot Audit on FailureIf a boot driver is blocked, boot continues in audit – safety net.
11Disabled:Script EnforcementDon't enforce scripts (PowerShell Constrained Language Mode, etc.).
12Required:Enforce Store ApplicationsApply policy to Store/UWP apps.
13Enabled:Managed InstallerTrust software deployed by a managed installer (e.g. Intune ext., MECM).
14Enabled:Intelligent Security Graph AuthorizationAllow apps with good Microsoft cloud reputation.
15Enabled:Invalidate EAs on RebootRe-check ISG/managed-installer cached trust at reboot.
16Enabled:Update Policy No RebootAllow policy updates without restart.
17Enabled:Allow Supplemental PoliciesBase may be extended by supplementals.
18Disabled:Runtime FilePath Rule ProtectionSkip the "path must be admin-writable only" check.

PowerShell
# List current options in a policy
([xml](Get-Content C:\WDAC\Base.xml)).SiPolicy.Rules.Rule.Option

# Print the option list supported by THIS build (the authoritative table)
Set-RuleOption -Help

# ADD an option (-Option takes the number only, not the name)
Set-RuleOption -FilePath C:\WDAC\Base.xml -Option 13          # managed installer
Set-RuleOption -FilePath C:\WDAC\Base.xml -Option 16          # no-reboot updates

# REMOVE an option
Set-RuleOption -FilePath C:\WDAC\Base.xml -Option 3 -Delete   # leave audit mode => ENFORCED

# Recommended "pilot safety" set
9,10 | ForEach-Object { Set-RuleOption -FilePath C:\WDAC\Base.xml -Option $_ }

B. File rule types (levels)

LevelMatches onBest for
HashAuthenticode/page hash of the fileUnsigned binaries. Breaks on every update.
FileNameOriginal file name (+ min version)Deny rules (e.g. block wmic.exe); weak for allow.
FilePublisherPublisher + product + file name + min versionMost apps – precise and survives updates.
PublisherPCA + publisher (CN) of leaf certTrusted vendors – all their products.
SignedVersionPublisher + minimum versionVendor allowed only above a given version.
PcaCertificateHighest intermediate CABroad vendor trust.
LeafCertificateExact signing certOne specific cert (changes on renewal).
RootCertificateRoot CARarely recommended – too broad.
WHQL / WHQLPublisher / WHQLFilePublisherWHQL-signed drivers (+ publisher / file)Kernel drivers.
FilePathPath or wildcardOnly admin-writable locations (C:\Program Files\...). Never user-writable paths.
Rule actionXMLEffect
Allow<Allow .../> / <AllowedSigner/>Permits matching files.
Deny<Deny .../> / <DeniedSigner/>Blocks matching files – wins over any allow.
FileAttrib<FileAttrib .../>Attributes used by signer-based rules to narrow scope (product name, file name, version) – "exceptions".

C. Add, modify and remove file rules

Add

PowerShell
$xml = "C:\WDAC\Base.xml"

# 1. ALLOW a publisher from an existing signed file
$rules = New-CIPolicyRule -DriverFilePath "C:\Program Files\Vendor\app.exe" -Level Publisher
Merge-CIPolicy -PolicyPaths $xml -OutputFilePath $xml -Rules $rules

# 2. ALLOW an unsigned file by hash
$rules = New-CIPolicyRule -DriverFilePath "C:\Tools\mytool.exe" -Level Hash
Merge-CIPolicy -PolicyPaths $xml -OutputFilePath $xml -Rules $rules

# 3. DENY a file (-Deny)
$rules = New-CIPolicyRule -DriverFilePath "C:\Windows\System32\mshta.exe" -Level FileName -Deny
Merge-CIPolicy -PolicyPaths $xml -OutputFilePath $xml -Rules $rules

# 4. ALLOW a folder by path (admin-writable only!)
$rules = New-CIPolicyRule -FilePathRule "C:\Program Files\CorpApps\*"
Merge-CIPolicy -PolicyPaths $xml -OutputFilePath $xml -Rules $rules

# 5. Scan an entire folder / install
New-CIPolicy -FilePath C:\WDAC\Scan.xml -ScanPath "C:\Program Files\Vendor" -Level FilePublisher -Fallback Hash -UserPEs
Merge-CIPolicy -PolicyPaths $xml, C:\WDAC\Scan.xml -OutputFilePath $xml

# 6. Merge Microsoft's recommended block rules (downloaded from Microsoft Learn)
Merge-CIPolicy -PolicyPaths $xml, C:\WDAC\MS_Recommended_Block_Rules.xml -OutputFilePath $xml

# 7. Merge the built-in vulnerable-driver blocklist
Merge-CIPolicy -PolicyPaths $xml, C:\Windows\schemas\CodeIntegrity\ExamplePolicies\RecommendedDriverBlock_Enforced.xml -OutputFilePath $xml

Modify

There is no "update in place" cmdlet for a single rule — change a rule by editing its XML attributes (or removing and re-adding it).

PowerShell
$path = "C:\WDAC\Base.xml"
[xml]$d = Get-Content $path
$ns = New-Object Xml.XmlNamespaceManager $d.NameTable; $ns.AddNamespace('si','urn:schemas-microsoft-com:sipolicy')

# Example: raise the minimum version on a FileAttrib / Allow rule
$node = $d.SelectSingleNode("//si:FileRules/*[@ID='ID_ALLOW_A_1']", $ns)
$node.SetAttribute('MinimumFileVersion','5.2.0.0')

# Example: change a rule's friendly name
$node.SetAttribute('FriendlyName','Approved HR tool v5.2+')

$d.Save($path)
Set-CIPolicyVersion -FilePath $path -Version "10.0.0.2"      # then recompile & redeploy

Remove

PowerShell
# List every file rule with its ID first
([xml](Get-Content C:\WDAC\Base.xml)).SiPolicy.FileRules.ChildNodes |
    Select Name, ID, FriendlyName, FileName, Hash | Format-Table -Auto

# Remove by ID: delete the rule, its FileRuleRef and (if a signer rule) the Signer + AllowedSigner
$path = "C:\WDAC\Base.xml"; $id = "ID_ALLOW_A_1"
[xml]$d = Get-Content $path
$ns = New-Object Xml.XmlNamespaceManager $d.NameTable; $ns.AddNamespace('si','urn:schemas-microsoft-com:sipolicy')

$d.SelectNodes("//si:FileRules/*[@ID='$id']", $ns)     | ForEach-Object { [void]$_.ParentNode.RemoveChild($_) }
$d.SelectNodes("//si:FileRuleRef[@RuleID='$id']", $ns) | ForEach-Object { [void]$_.ParentNode.RemoveChild($_) }
$d.Save($path)

Set-CIPolicyVersion -FilePath $path -Version "10.0.0.3"
Check references. A rule ID that is still referenced in <SigningScenarios> but no longer exists makes the policy invalid and ConvertFrom-CIPolicy will fail – that is your free validation. The ConfigCI module also exposes Remove-CIPolicyRule; check Get-Help Remove-CIPolicyRule -Full on your build before relying on it.

5How to back up policies

Back up three things: source XML (the real asset), compiled .cip files, and a record of what was active.

PowerShell
# ===== Backup-WDACPolicy.ps1 (run elevated) =====
param(
  [string]$SourceXmlDir = "C:\WDAC",                       # where your master XML files live
  [string]$BackupRoot   = "D:\WDAC-Backups"
)
$stamp = Get-Date -Format "yyyyMMdd_HHmmss"
$dest  = Join-Path $BackupRoot "$env:COMPUTERNAME`_$stamp"
New-Item -ItemType Directory -Path "$dest\Active","$dest\EFI","$dest\XML" -Force | Out-Null

# 1. Compiled policies (OS partition)
$ci = "$env:windir\System32\CodeIntegrity"
Copy-Item "$ci\CiPolicies\Active\*" "$dest\Active" -ErrorAction SilentlyContinue
Copy-Item "$ci\SiPolicy.p7b"        $dest           -ErrorAction SilentlyContinue

# 2. Compiled policies (EFI partition)
$drive = 'Y:'
mountvol $drive /S
try {
  Copy-Item "$drive\EFI\Microsoft\Boot\CiPolicies\Active\*" "$dest\EFI" -ErrorAction SilentlyContinue
  Copy-Item "$drive\EFI\Microsoft\Boot\SiPolicy.p7b"        "$dest\EFI" -ErrorAction SilentlyContinue
} finally { mountvol $drive /D }

# 3. Source XML
Copy-Item "$SourceXmlDir\*.xml" "$dest\XML" -ErrorAction SilentlyContinue

# 4. State record + hashes
Get-CimInstance Win32_DeviceGuard -Namespace root\Microsoft\Windows\DeviceGuard |
   Select CodeIntegrityPolicyEnforcementStatus, UsermodeCodeIntegrityPolicyEnforcementStatus |
   ConvertTo-Json | Out-File "$dest\state.json"
if (Get-Command CiTool.exe -ErrorAction SilentlyContinue) { CiTool.exe -lp -json | Out-File "$dest\citool-policies.json" }
Get-ChildItem $dest -Recurse -File | Get-FileHash -Algorithm SHA256 |
   Select Hash, @{n='File';e={$_.Path.Replace($dest,'')}} | Export-Csv "$dest\hashes.csv" -NoTypeInformation

# 5. Optional: zip + prune backups older than 30 days
Compress-Archive -Path "$dest\*" -DestinationPath "$dest.zip" -Force
Get-ChildItem $BackupRoot -Directory | Where LastWriteTime -lt (Get-Date).AddDays(-30) | Remove-Item -Recurse -Force
Write-Host "Backup complete: $dest.zip"
Restore
# Restore from a backup folder (reboot afterwards on file-copy deployments)
$b = "D:\WDAC-Backups\PC01_20261014_101500"
Remove-Item "$env:windir\System32\CodeIntegrity\CiPolicies\Active\*.cip" -Force
Copy-Item "$b\Active\*.cip" "$env:windir\System32\CodeIntegrity\CiPolicies\Active\"
Restart-Computer
Tip. Keep the XML in Git (or a locked file share): tag every deployed version (base-v10.0.0.7), and store the policy GUID in the commit message. XML is diff-able; .cip is not.
Signed policies. Also back up the signing certificate and private key (HSM / vault). Lose them and you cannot update or remove the policy.

6Rollback after a policy failure & best practices

Decide fast: can the machine still log on? That chooses your path.

Rollback procedures

1 · Soft rollback (preferred): redeploy known-good or switch to audit

PowerShell
$xml = "C:\WDAC\Base.xml"
Set-RuleOption -FilePath $xml -Option 3                          # back to AUDIT
$v = [version]([xml](Get-Content $xml)).SiPolicy.VersionEx
Set-CIPolicyVersion -FilePath $xml -Version ([version]::new($v.Major,$v.Minor,$v.Build,$v.Revision+1))   # MUST be higher
$id = ([xml](Get-Content $xml)).SiPolicy.PolicyID
ConvertFrom-CIPolicy -XmlFilePath $xml -BinaryFilePath "C:\WDAC\Out\$id.cip"
CiTool.exe --update-policy "C:\WDAC\Out\$id.cip"                 # Win11 – immediate
# or (all builds)
Copy-Item "C:\WDAC\Out\$id.cip" "$env:windir\System32\CodeIntegrity\CiPolicies\Active\" -Force; Restart-Computer

2 · Hard rollback: remove the policy (unsigned policies)

PowerShell
$id = "{11111111-2222-3333-4444-555555555555}"

# Windows 11 22H2+
CiTool.exe --remove-policy $id

# All builds – OS partition
Remove-Item "$env:windir\System32\CodeIntegrity\CiPolicies\Active\$id.cip" -Force
# All builds – EFI partition
mountvol Y: /S
Remove-Item "Y:\EFI\Microsoft\Boot\CiPolicies\Active\$id.cip" -Force -ErrorAction SilentlyContinue
mountvol Y: /D

# Legacy single-policy format
Remove-Item "$env:windir\System32\CodeIntegrity\SiPolicy.p7b" -Force -ErrorAction SilentlyContinue

Restart-Computer

3 · Offline recovery (WinRE command prompt)

CMD (WinRE)
:: find the Windows drive (usually D: or C: inside WinRE)
dir C:\Windows\System32\CodeIntegrity\CiPolicies\Active
del C:\Windows\System32\CodeIntegrity\CiPolicies\Active\{GUID}.cip

:: EFI copy
mountvol S: /S
del S:\EFI\Microsoft\Boot\CiPolicies\Active\{GUID}.cip
del S:\EFI\Microsoft\Boot\SiPolicy.p7b
wpeutil reboot

4 · Managed deployments

ChannelRollback
IntuneReplace the assigned policy with the last-good/audit version (higher version), or unassign; for custom OMA-URI send the replacement base64 payload. Sync device.
MECMSwitch deployment to Audit only or redeploy last-good policy.
GPOSet to Disabled / point to a good .cip/.p7b and gpupdate /force + reboot.
Signed policies + Secure Boot. If a signed policy has no Unsigned option and you delete the file, the machine may refuse to boot. Recovery requires a signed update policy, or clearing Secure Boot / resetting the policy via firmware as a last resort. This is why signing happens only after a policy is mature.

Best practices

Design
  • Start from DefaultWindows_Audit.xml or AllowMicrosoft.xml; never from zero.
  • One slim base + several supplementals per team/app.
  • Prefer FilePublisher → fallback Hash. Use FileName mainly for Deny.
  • FilePath only for admin-writable folders; avoid wildcards on user paths.
  • Merge Microsoft recommended block rules and the vulnerable driver blocklist.
  • Use Managed Installer (13) and/or ISG (14) to cut rule maintenance.
Rollout
  • Audit first for 2–4 weeks; review events 3076 / 8028 and build rules from them.
  • Rings: lab VM → IT pilot → one department → all.
  • Enable options 9 and 10 and 16 during pilots.
  • Always increment VersionEx; use meaningful PolicyName.
  • Take a VM snapshot / restore point before enforcing.
  • Enforce only when the audit log is clean for a full business cycle.
Operations
  • Source XML in Git with change review and tags.
  • Automate backup (section 5) before every change.
  • Forward CodeIntegrity events to SIEM / Defender Advanced Hunting (DeviceEvents AppControl*).
  • Document an exception process: request → supplemental policy → expiry date.
  • Rehearse the WinRE recovery at least once per team.
Security
  • Sign policies only once stable; protect keys in an HSM/Key Vault.
  • Keep PowerShell in Constrained Language Mode (script enforcement on, option 11 absent).
  • Block known LOLBins that you do not need (e.g. mshta.exe, wmic.exe, msbuild.exe as appropriate).
  • Pair with HVCI / Secure Boot / BitLocker (protect CiPolicies folder integrity).
  • Treat Hash rules as temporary – re-scan after app updates.
